## 1. Контекст задачи
Штатная официальная интеграция Twinkly в Home Assistant (основанная на библиотеке `ttls`) сильно урезана: она умеет только включать/выключать свет, менять яркость/статичный цвет и переключать базовый режим (`Color`, `Movie`, `Playlist`), не давая гибкого управления.

Были сформулированы требования к собственной кастомной интеграции (`custom_component`):
1. **Группировка гирлянд** (созданных в приложении на телефоне).
2. **Поддержка донгла Twinkly Music**.
3. **Скачивание и загрузка эффектов** из облака Twinkly в гирлянду.
4. **Полноценная работа с плейлистами** (выбор, редактирование, сменяемость).
5. **Управление пресетами** (включая музыкальные пресеты донгла).
6. **Кастомные музыкальные пресеты** и эффекты.

## 2. Сводная оценка реализуемости

| № | Фича | Реализуемость | Сложность | Архитектурное решение / Протокол |
|---|---|---|---|---|
| **1** | **Группировка гирлянд** | **100%** | Низкая/Средняя | Чтение конфигурации синхронизации (`/xled/v1/sync`, `/gestalt`), маршрутизация команд через `master`-контроллер. |
| **2** | **Twinkly Music** | **~85%** | Средняя | Управление режимом через гирлянду (`/xled/v1/music/...`, `led/mode: music`). |
| **3** | **Эффекты с облака** | **Реально с нюансами** | Высокая | В облаке лежат шаблоны; гирлянде нужен покадровый бинарный буфер под конкретный 2D/3D маппинг. Загрузка в память: `POST /xled/v1/movies`. |
| **4** | **Плейлисты** | **100%** | Низкая | Полный CRUD по локальному API (`/xled/v1/playlist`, `/xled/v1/playlist/current`). |
| **5** | **Музыкальные пресеты** | **~90%** | Средняя | Эндпоинты драйверов: `/xled/v1/music/drivers`, `/music/drivers/sets`. |
| **6** | **Свои муз. пресеты** | **Реально** | Средняя | Потоковый UDP-режим `rt` (порт 7777, до 60 FPS) либо компиляция видео в `.movie` под координаты диодов. |

## 3. Подробный технический разбор

### 3.1. Группировка гирлянд
* **Механика Twinkly:** В группе устройств выделяется один `master` и подчиненные `slave`. У них общий `group_uid`.
* **Проблема штатной интеграции:** Шлет команды на каждое устройство независимо. При отправке команды на `slave` группа часто рассинхронизируется или команда игнорируется.
* **Решение:** В интеграции объединять устройства с одинаковым `group_uid` в единый `Light Group`, отправляя команды управления эффектами строго на `master`.

### 3.2. Донгл Twinkly Music
* Донгл вещает аудио-спектр в сеть по Wi-Fi/UDP.
* Сама гирлянда переводится в режим приема звука через локальный REST API: `POST /xled/v1/led/mode` с `{"mode": "music"}`.
* Интеграция в HA может полноценно переключать режимы и отслеживать статус подписки гирлянды на звук.

### 3.3. Облако эффектов и загрузка в память
* **Важная особенность:** Гирлянда не генерирует анимации сама на лету. В её памяти хранятся уже скомпилированные байт-массивы кадра под точные координаты диодов (`/xled/v1/led/layout/full`).
* **Как делать в HA:**
  * Читать геометрию гирлянды.
  * Хранить библиотеку скачанных эффектов на диске Home Assistant (обходя лимит флеш-памяти гирлянды).
  * Загружать нужный ролик через `POST /xled/v1/movies/new` и `POST /xled/v1/movies/full`.

### 3.4. Плейлисты
* API предоставляет полный доступ:
  * `GET /xled/v1/playlist` — список треков, ID и тайминги (`duration`).
  * `POST /xled/v1/playlist` — перезапись списка.
  * `GET / POST /xled/v1/playlist/current` — текущий воспроизводимый эффект.
* В Home Assistant можно вывести в виде сущности `media_player` или списка `select`.

### 3.5. Кастомные эффекты и реалтайм светомузыка
* **Режим `rt` (Real-Time):** гирлянда принимает сырые RGB-кадры по UDP (порт 7777). Это позволяет делать любую светомузыку с ПК/сервера без износа флеш-памяти.
* Готовый проект с поддержкой Twinkly UDP — **LedFx**.

## 4. Существующие наработки и репозитории
Единой готовой интеграции для Home Assistant со всеми этими фичами **в HACS нет**. Ниша полностью свободна.

Однако есть отличные модули и документация, которые можно использовать как базу:
1. **`scrool/xled` и `xled-docs` (GitHub):**  
   Базовая документация и Python-библиотека по закрытому локальному протоколу XLED.
2. **`Anders-Holst/xled_plus` (GitHub):**  
   Пакет генерации эффектов, работы со звуком и 2D/3D маппингом диодов на Python.
3. **`stitch1968/ttls` (GitHub):**  
   Асинхронная библиотека на `aiohttp`, используемая текущим официальным компонентом HA.
4. **`patrickbs96/ioBroker.twinkly` (GitHub):**  
   Пример более продвинутой реализации для ioBroker с поддержкой режимов `music`, `playlist`, `rt`.
